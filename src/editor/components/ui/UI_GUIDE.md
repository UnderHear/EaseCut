# UI 组件公共规范

本目录用于存放可复用的编辑器 UI 基础组件。新增组件应优先遵循本规范；组件只负责通用呈现、交互和可访问性，不承载具体业务规则或领域状态。

## 设计原则

- 单一职责：一个组件解决一种明确的 UI 问题。
- 优先组合：通过子组件、插槽或明确的 props 组合复杂界面，不复制相似实现。
- 行为可预测：相同输入产生相同呈现和回调，不读取随机值、当前时间或隐式全局状态。
- API 清晰：状态、事件、禁用条件和错误反馈通过类型明确表达。
- 业务解耦：业务校验、数据提交、领域命令和持久化逻辑由上层负责。
- 破坏性重构时删除失效实现、过渡适配器和废弃样式，不长期维护两套 UI 规则。

## 视觉系统

- 使用编辑器已有的颜色、圆角、间距、字号和阴影设计值，避免为单个组件创造新的主题值。
- 交互表面应保持稳定的盒模型；边框或焦点变化不能造成尺寸跳动。
- 默认态、悬停态、聚焦态、按下态、禁用态、错误态和选中态只在确实需要时实现。
- 状态不能只依赖颜色表达，应同时提供文字、图标、形状或焦点变化等信息。
- 同一类控件的高度、内边距、边框、背景和文字层级应保持一致。
- 不添加无产品需求的渐变、发光、复杂动画或装饰性状态。
- 动画应短且可中断；尊重 `prefers-reduced-motion`，不使用任意延时模拟状态。

## CSS 作用域

- 选择器使用 `ec-` 命名空间，样式文件与组件放在同一目录。
- 避免使用裸元素选择器、过深的上下文选择器和 `!important`。
- 共享视觉规则应集中在可识别的基础选择器中，组件特有的布局和行为样式留在组件内部。
- 优先使用设计 token；如果内容通过 Portal 挂载到编辑器根节点之外，不能假设祖先 CSS 变量或祖先滚动条样式仍然可用。
- Portal 内容必须自行声明所需的颜色、边框、阴影、滚动条和层级规则，或由明确的主题容器提供这些值。
- 不用 CSS 偶然的布局结果实现业务约束；可见性、层级、碰撞和定位规则应由组件逻辑明确处理。

## API 与状态

- 可编辑值优先使用受控接口；受控值、默认值和变更回调的语义必须明确，不能在两种模式之间静默切换。
- 原生属性应按需透传，移除会破坏无障碍或表单行为的属性时必须有明确理由。
- 回调名称表达用户行为，例如 `onOpenChange`、`onValueChange`、`onCommit`；不要暴露内部 DOM 事件作为唯一业务接口。
- 组件内部状态只保存交互所需的临时状态；派生值在渲染时计算，不保存可由 props 推导的副本。
- 禁用、加载、空数据和错误状态必须有确定行为，不能依赖永久 spinner 或静默失败。
- 组件卸载、关闭或任务取消时，清理事件监听器、定时器、动画帧、对象 URL、Worker 和其他运行时资源。

## 焦点与键盘

- 每个可交互控件都必须有可见且稳定的焦点路径。
- 键盘行为应等价于鼠标行为；至少覆盖 Tab、Enter、Space、Escape 和方向键等适用按键。
- 弹出层打开后，焦点移动、返回和关闭规则必须明确；关闭后通常恢复到触发器。
- 输入文字时不得误触发编辑器全局快捷键。
- 焦点、选中、展开、禁用和错误状态应通过可访问属性或可读文本暴露给辅助技术。

## 浮层、Portal 与定位

- 会被父元素 `overflow` 裁切的菜单、提示、弹窗和列表，应使用 Portal 挂载到合适的顶层容器。
- 需要越过滚动容器时使用 `position: fixed`，根据触发器的视口矩形计算位置；仅脱离文档流但仍受裁切时，不应只使用 `position: absolute`。
- 浮层应处理视口边界、滚动、窗口缩放、触发器尺寸变化和触发器卸载。
- 浮层打开期间监听的 pointer、keydown、scroll 和 resize 事件必须在关闭或卸载时对称清理。
- 点击外部、Escape、失焦和路由或面板关闭都应有明确的收起行为。
- 层级使用可解释的 z-index 关系，不通过无限增大的数值解决层叠冲突。

## 性能与资源

- 交互热路径中避免克隆大型对象、重复扫描全量数据或触发无关组件重渲染。
- 高频 pointer、scroll、resize 和媒体更新应合并到动画帧或使用节流策略。
- 不为不可见内容持续创建昂贵 DOM、图片、波形或媒体资源。
- 事件监听器和 DOM 引用使用局部生命周期管理，禁止依赖全局可变单例掩盖清理问题。

## 提交前检查

- 组件是否只包含通用 UI 规则，没有混入业务判断？
- 是否复用了既有设计值，并且没有新增无依据的视觉状态？
- 是否覆盖了鼠标、键盘、焦点、禁用、错误、取消和卸载路径？
- Portal、事件监听器、计时器和其他资源是否有对称清理？
- 是否补充了与风险相称的测试，并通过 lint、typecheck、test 和 build？
